# SSE 执行证据本地存档

用户要求保留执行过程，并在 Runtime 回收和远端保留期结束后继续读取。当前真实 trace v1.4 在部分已结束任务上返回 `workerTrajectory.status=unavailable`；轮询不足以保证捕获很快结束的命令。

## 修复边界

- 使用桌面 Go 层已经收到、已经归一化的 SSE 事件，存入每个 session/invocation 的独立 JSONL 文件。只保存执行事件（工具、推理、worker 状态、终态）；不新增远端请求，不根据标题或文本推测 worker 身份。
- 事件来源 `sourceType` 随归一化事件保留。只有明确 codex/worker 来源的事件进入 worker 分类；缺失时间不补当前时间。
- 本地读取将事件投影与远端 trace 合并，优先使用远端步骤身份和度量；仅使用确切 sourceEventId 或 toolId 去重，不通过文案相似度匹配。
- call/result 归并到同一个工具执行；完整持久化内容可覆盖流式增量，重放的明确 eventId/part 不重复累计。
- JSONL 追加在原生流处理线程进行，不阻塞 WebView 渲染，也不启动额外轮询。终态和每条执行事件都写完后再向前端交付，避免 App 退出时留下未刷新的应用缓冲。
- trace 快照的读、合并和写在同一个缓存锁内完成。晚到的 running 快照不覆盖已保存的终态；删 session 后的事件和快照均不可恢复已删除内容。
- 只有本地 SSE 时明确标注来源和完整性未知；不将收到 done 等同于完整远端 trace。磁盘写入失败必须记录为本地存档不可用，不能声称缓存成功。

## 验证

覆盖两次轮询之间完成的命令、重复投递、同一事件多 part、缺失时间、远端只有 final、晚到旧快照、并发快照和事件写入、删除与在途事件竞态。使用真实 SSE 协议形状和服务层集成，不依赖仅验证 CSS 字符串的断言。
