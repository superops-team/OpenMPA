# Runtime 选择稳定性修复

## 范围与验收

用户反馈：Runtime 选择页面选中后会跳动。沿用当前 main 的未提交工作，只修复此选择流程的布局；本机直接替换安装，不备份。版本保持 0.1.4。

验收要求：选择前、绑定中、成功或失败后的列表行、按钮、标题和滚动位置不发生布局位移；保留绑定中的禁用状态、权威返回后的选中状态、错误提示和失败重试。支持中英文、明暗主题及窄窗口。

## 根因证据

在生产 React 页面注入模拟 MyGo transport，延迟 `Platform.BindRuntime`，对 12 行目录滚动到中部，逐帧采集几何与滚动数据。

修复前 32 组测试均出现页面高度变化，最大布局变化 61px；按钮文案切换的最大位移为 44.859375px。错误/成功提示插到设置标题与卡片之间，提示清除或插入时改变页面高度，并触发浏览器滚动锚定。按钮使用内容宽度，在三种状态文案间切换时挤压文本列。目录行的 DOM 保持复用，列表重建不是此次根因。

原有默认设计验证只检查表单对齐与最终选中状态，已通过的旧报告未捕获中间布局变化。因此将逐帧几何验证纳入默认 `npm run design:verify`，并对已记录的缺陷报告应用相同的 `<0.5px` 阈值，确认失败。

修复前证据：`.openmpa/runtime-selection/2026-10-29T02-22-45.506Z/report.json`，包含 32 组成功/失败测试的帧数据和截图。

## 实现

- Runtime 反馈放入筛选框下方固定两行高度的区域；长错误可滚动读取，不再挤动目录。其他设置页保留原有提示显示。
- 按钮的三种本地化文案叠放在同一个 CSS Grid 单元，按最长文案预留尺寸；只暴露当前状态的可访问文本。
- Runtime 文本列允许缩小与断行，按钮保持完整宽度，避免窄窗口内挤压控件。
- 继续使用现有 Button、状态文本、选择颜色和语义 token，无布局动画或手动滚动补偿。
