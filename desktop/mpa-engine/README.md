# Bundled MPA lifecycle engine

This helper adapts the unmodified Studio orchestration shipped in **VeADK Python 1.1.19**, corresponding to upstream Studio PR #1182. `uv.lock` pins the full dependency graph. The application does not execute a user-supplied CLI, open an HTTP port or depend on a Python installation on the user's machine.

`engine.py` implements a private JSON line protocol over stdin/stdout. Go initializes it with one verified cloud account, principal-derived owner, private journal path and in-memory credentials. Fixed operations wrap Studio's creation routes and journal, or its managed resource cleanup. Only typed results and allowlisted diagnostic fields reach the frontend. Raw SDK stderr is discarded by the host. No keys are written to task rows or command arguments.

`creation_runner.py` adapts the pinned Runtime readiness check and observes Worker, VPC/subnet, APIG/IM gateway, PostgreSQL Workspace/branch/compute, and OpenViking reads. Only the original terminal-state failure triggers enrichment: structured resource status first, then an exact resource audit lookup using the verified deployment credentials and region. Worker additionally inspects the failed release of the uniquely named FaaS function (`agentkit-builtin-tools-<ToolId>`), checking function identity and release time without reading instance logs. AgentKit dependency audit errors require an exact Runtime/Tool receipt and a complete window without competing AgentKit writes; FaaS errors must match the exact function name or its creation receipt, and PrivateLink errors must share a single dependency request identity. Errors superseded by successful retries are discarded. Other services require an exact resource ID and, for database subresources, the selected branch/compute IDs. Phase changes and successful reads discard earlier observations. SQL failures retain SQLSTATE even when a pinned boundary suppresses exception chaining. Missing permissions, ambiguous evidence and lookup timeouts preserve the original failure. The total lookup budget is 12 seconds. Only safe error codes and cloud request IDs enter the existing diagnostic journal; audit bodies, messages, environment variables, SQL text, credentials and log URLs are never forwarded. Diagnostics issue no creation, update or deletion requests and do not change provisioning retries or resource ownership checks.

`scripts/prepare-mpa-engine.py` prepares an isolated uv project environment, then packages the managed CPython interpreter, site packages, bridge and manifest into a tar archive. This preserves native library directories such as `.dylibs`. Pure-Python generated SDK service packages with no package data or filesystem-relative module access are retained in an importable zip; core/native code, resource-bearing packages, licenses and metadata stay as ordinary files. This avoids extracting about 27,000 tiny files without removing any SDK capabilities. The Go extractor rejects traversal, links and duplicate files, bounds archive size, uses private modes and caches by archive SHA-256. Builds target the host architecture; the supported release currently targets macOS arm64.

VeADK is licensed under Apache-2.0. CPython uses the PSF license; transitive dependencies retain their respective licenses, including license files in `*.dist-info` and the Python distribution. The archive includes those notices and metadata. This adapter's source belongs to OpenMPA and follows the repository license. Updating VeADK requires reviewing the protocol and safe cleanup contracts, regenerating the lock/archive and rerunning the Python, Go, React, browser and packaged-engine tests.

Diagnostic lookups also respect the enclosing creation deadline, reserving 250 ms to rethrow the original failure. If no time remains, lookup is skipped; a late terminal resource failure must not be replaced by the runner's overall timeout. Cancellation is still propagated.

Tests use fake cloud clients or a fake runner. They must never provision or delete real cloud resources. Success-path comparisons verify that adapted Worker, VPC/subnet, APIG and PostgreSQL calls preserve the pinned SDK's request bodies, call counts, saved IDs and return values without issuing diagnostic queries. The packaged smoke test supplies dummy credentials and invokes only local configuration and task-list operations.
